```text

```


其中 4 个 GPU test 覆盖：

1. producer side stream 的 ready event 经 per-group gate stream 传入 NCCL；
2. `ScheduledWork.wait()` 只向 consumer stream 插入依赖，不调用
   `torch.cuda.synchronize()`，也不等待无关 side stream；
3. 不同 process group 使用不同 gate stream，已经 ready 的 B 不继承慢 A 的
   producer dependency，但 host launch log 仍为 `A -> B`；
4. scheduler `finish_window()` + `close()` 后，原始 ProcessGroup collective 仍能
   独立执行。

以下场景全部通过：

test 进一步确认 `ScheduledWork.wait()` 本身没有调用该 API。

## WorkNCCL completion capability gate

新增：

- `examples/m45_completion_gate_worker.py`；
- `examples/run_m45_completion_gate.py`。

harness 在真实两 rank all-reduce 前排入约 0.29 秒 CUDA sleep，制造稳定的
physical-incomplete 窗口。

### 默认模式

| 观测 | rank 0 | rank 1 |
|---|---:|---:|
| wait 前 `is_completed()` | false | false |
| `Work.wait()` host 时间 | 0.102 ms | 0.103 ms |
| wait 后 `is_completed()` | false | false |
| 64 次 completion poll | 0.118 ms，全部 false | 0.116 ms，全部 false |
| wait 返回后 consumer event | false | false |
| consumer stream sync 后 event | true | true |
| 最终 `is_completed()` | true | true |
| all-reduce 数据 | 正确 | 正确 |

结论：当前环境的 `WorkNCCL.is_completed()` 可以作为 nonblocking physical
completion probe；`Work.wait()` 保持 stream-ordered 语义，不能用于释放 physical
outstanding slot。

### `TORCH_NCCL_BLOCKING_WAIT=1`

wait host 时间分别为 `286.648 ms` 和 `286.123 ms`；返回后
`is_completed()==true`，数据正确。该环境变量会把 wait 改成 CPU blocking 行为，
不应在 scheduler wrapper 中自行模拟。

### finite timeout

`Work.wait(timeout=10ms)` 在两 rank 均抛出 `DistBackendError`：watchdog 报告
collective 运行 10 ms 后超时。host 侧分别约 `496.334 ms` 和 `497.682 ms` 才收到
异常。超时会 abort communicator，正常 ProcessGroup teardown 可能进入长时间
watchdog/诊断路径，因此 capability harness 使用一次性子进程记录后直接退出，
不尝试恢复或复用 communicator。

这意味着 `ScheduledWork.wait(timeout=...)` 的总 deadline 只保证 wrapper 正确扣除
bind 时间；一旦把有限 timeout 传给 WorkNCCL，它是破坏 communicator 的错误边界，
不是普通的“尚未完成，返回 false”查询。普通完成检测必须使用经过验证的
`is_completed()` polling。

## 结论

M4.5 的 producer bridge、per-group gate isolation、consumer stream dependency、
physical completion polling、worker launch 和回归测试均在替代 GPU 环境通过。
M4.5 可以结束，后续可以进入 M5 Megatron DP adapter；若未来重新获得 3090 容器，
只需把同一 harness 作为硬件回归重跑，不再阻塞当前阶段。
